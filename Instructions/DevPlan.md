# DevPlan — LuzParaguay

## Обзор проекта

**LuzParaguay** — мобильное приложение для мониторинга отключений электроэнергии в Парагвае в реальном времени. Объединяет официальные данные ANDE с краудсорсингом пользователей, отправляет WhatsApp-уведомления при изменении статуса электроснабжения в выбранном районе.

---

## Технологический стек

| Слой | Технология |
|---|---|
| Парсер | Python 3.10 + Scrapy / Playwright |
| Backend API | Python (FastAPI) |
| База данных | PostgreSQL + PostGIS |
| Мобильный фронтенд | Flutter (iOS + Android) |
| Уведомления (Push) | Firebase Cloud Messaging (FCM) |

| Геокодирование | OpenStreetMap (Nominatim) |

### Этап 1: Data Engine (Парсер)

**Цель:** Автоматический сбор данных об отключениях из трёх источников.

#### 1.1 Источники данных
- [ ] **Primary:** Парсинг сайта ANDE — раздел «Cortes Programados» (плановые отключения)
  - Реализовать на Scrapy или Playwright (с учётом возможного JS-рендеринга)
  - Обработка случаев, когда данные публикуются в PDF
- [ ] **Secondary:** Запросы к внутреннему API `consultas.ande.gov.py` (аварийные отключения)
- [ ] **Social:** Мониторинг Twitter-аккаунта `@ANDEOficial` для оперативных новостей

#### 1.2 Алгоритм обработки данных
- [ ] **Fetch:** Ежечасный (можно каждые 15 мин) запрос ко всем источникам через Cron / APScheduler
- [ ] **Clean:** Нормализация названий районов (унификация написания, убрать опечатки)
- [ ] **Geocode:** Определение координат районов через OpenStreetMap Nominatim API
- [ ] **NIS → Фидер:** Реализовать логику определения `Nro de Alimentador` по `Nro de NIS` пользователя — это позволяет уведомлять адресно по конкретной линии
- [ ] **Compare:** Проверка на дубликаты перед записью в БД
- [ ] **Broadcast:** Отправка триггера в систему уведомлений при появлении новых событий

#### 1.3 База данных
- [ ] Проектирование схемы: таблицы `outages`, `users`, `user_reports`, `subscriptions`, `feeders`
- [ ] Настройка PostGIS для хранения геоточек и полигонов районов
- [ ] Написание миграций (Alembic)

### Этап 2: Backend API

**Цель:** REST API для мобильного приложения.

- [ ] `GET /outages` — актуальный список отключений
- [ ] `POST /reports` — принять геометку от пользователя («У меня нет света»)
- [ ] `GET /reports` — получить метки пользователей в заданном радиусе
- [ ] `POST /subscriptions` — подписать пользователя на уведомления по району / фидеру
- [ ] `DELETE /subscriptions/{id}` — отписаться
- [ ] `POST /users` — регистрация, привязка NIS-номера

**Логика валидации краудсорсинга:**
- [ ] Статус инцидента подтверждается, если **3 и более** пользователей в радиусе **500 м** отметили проблему
- [ ] Автоматическое снятие метки, если после подтверждения пользователи перестали сообщать о проблеме

---

### Этап 3: Система уведомлений

**Цель:** Своевременно оповещать пользователей об изменениях статуса электроснабжения.

- [ ] **Firebase Cloud Messaging (FCM):** Интеграция для нативных Push-уведомлений (iOS и Android)
- [ ] Логика триггеров:
  - Новое плановое отключение добавлено для района пользователя
  - Аварийное отключение подтверждено краудсорсингом
  - Электричество восстановлено
- [ ] Управление подписками: пользователь выбирает районы и/или конкретный фидер по NIS

---

### Этап 4: Мобильное приложение (Flutter)

**Цель:** Кроссплатформенный клиент (iOS + Android).

#### 4.1 Экраны
- [ ] **Главный экран:** Интерактивная карта с тепловыми зонами (горячие точки отключений)
- [ ] **Список отключений:** Официальные плановые и аварийные отключения
- [ ] **Кнопка «У меня нет света»:** Определить геолокацию → отправить метку на сервер
- [ ] **Комментарии:** Возможность добавить описание к метке
- [ ] **Настройки подписок:** Выбор районов и привязка NIS-номера счёта
- [ ] **История:** Журнал прошлых отключений

#### 4.2 Дизайн
- [ ] **Dark Mode** по умолчанию (экономия заряда при отсутствии электричества — ключевое UX-требование!)
- [ ] Минималистичный UI, адаптированный под слабые устройства

## Порядок приоритетов (MVP)

1. **Парсер ANDE** → запись в БД (без этого нет данных)
2. **API `/outages`** → базовый список для отображения
3. **Flutter-приложение**: карта + список отключений (только чтение)
4. **Push-уведомления (FCM)** по районам
5. **Кнопка краудсорсинга** + валидация
6. **NIS → Фидер** (точечные уведомления по линии)

## Риски и примечания

| Риск | Митигация |
|---|---|
| ANDE меняет структуру сайта | Мониторинг изменений, быстрое обновление парсера |
| Данные в PDF | Реализовать PDF-парсер (PyMuPDF / pdfplumber) |
| Блокировка скрапинга | Использовать Playwright + ротацию User-Agent / задержки |
| Злоупотребление кнопкой краудсорсинга | Правило «3+ пользователя в 500м», rate-limiting по IP/аккаунту |
