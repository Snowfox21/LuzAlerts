# MVP Plan — LuzParaguay

## Цель MVP

Рабочее приложение, которое:
1. Показывает актуальные отключения от ANDE на карте и в списке
2. Позволяет пользователю отметить «У меня нет света»
3. Присылает push-уведомление, когда в подписанном районе появляется отключение

---

## Текущий статус компонентов

| Компонент | Статус | Что готово |
|-----------|--------|------------|
| **Scraper** | ✅ Работает | Парсинг ANDE HTML, геокодинг, запись в БД |
| **Backend API** | ✅ Готов | `/users`, `/outages`, `/reports`, `/subscriptions` |
| **БД** | ✅ Готова | PostgreSQL + PostGIS, все 4 таблицы |
| **Краудсорсинг** | ✅ Готов | Валидация 3+ меток в 500м (`crowdsource.py`) |
| **Mobile UI** | ⚠️ Частично | Структура есть, UI экраны не готовы |
| **Push-уведомления** | ❌ Не готово | FCM токен хранится, но отправка не реализована |

## Что нужно для MVP (приоритизированный список)

### Приоритет 1 — Критично (без этого MVP не работает)

#### 1.1 Push-уведомления (FCM)
**Что нужно:**
- Интеграция `firebase-admin` в backend
- Функция `send_push(fcm_token, title, body)`
- Триггеры отправки:
  - Новое плановое отключение → пользователям, подписанным на этот `barrio` или `feeder_number`
  - Краудсорсинговое отключение подтверждено (≥3 меток) → пользователям в зоне
- Место: новый файл `backend/app/notifications.py`, вызов из `scraper/processor.py` и `backend/app/routers/reports.py`

#### 1.2 Мобильное приложение — базовые экраны
**Что нужно:**
- **Главный экран (карта):** MapView с маркерами отключений из `GET /outages/`; цвет маркера по статусу (`planned` — жёлтый, `active` — красный)
- **Список отключений:** FlatList с карточками, фильтр по статусу
- **Кнопка «Нет света»:** определение геолокации → `POST /reports/` → тост с подтверждением
- **Настройки:** ввод barrio или NIS → `POST /subscriptions/`, сохранение FCM токена через `POST /users/`
- Dark Mode по умолчанию (обязательно — пользователи будут открывать приложение при отключённом свете)

---

### Приоритет 2 — Важно для качества

#### 2.1 Scraper: PDF-парсинг
ANDE часто публикует данные в PDF. Без этого ~30-40% отключений пропускается.
- Библиотека: `pdfplumber` или `PyMuPDF`
- Логика: если страница ANDE возвращает ссылку на PDF — скачать, распарсить текст, нормализовать

#### 2.2 Регистрация FCM-токена в приложении
- При старте приложения: `POST /users/` с `device_id` + `fcm_token`
- Обновление токена при его изменении (Firebase обновляет токены)

#### 2.3 Восстановление электричества — уведомление
- В scraper: если статус отключения изменился на `resolved` → отправить push подписчикам

---

### Приоритет 3 — После MVP

| Фича | Причина отложить |
|------|-----------------|
| WhatsApp-уведомления (Twilio) | Push через FCM достаточно для MVP |
| NIS → Feeder маппинг | Требует данных от ANDE, сложная интеграция |
| Twitter-мониторинг | Низкая надёжность, API платный |
| Alembic-миграции | В dev `create_all` работает, нужно перед prod-деплоем |
| Admin-панель | Можно управлять через psql напрямую |
| История отключений | Данные копятся сами, экран можно добавить позже |

## Чеклист задач для MVP

- [ ] Создать `backend/app/notifications.py` — функция отправки FCM push
- [ ] Вызывать push из `processor.py` при появлении нового отключения
- [ ] Вызывать push из `crowdsource.py` при подтверждении краудсорсинговой метки
- [ ] Добавить push при смене статуса на `resolved`

- [ ] Добавить PDF-парсинг в `ande_parser.py` (pdfplumber)
- [ ] Протестировать нормализацию на реальных PDF от ANDE

- [ ] Список отключений: FlatList + фильтр по статусу

- [ ] Регистрация устройства: `POST /users/` с FCM-токеном при старте

ANDE сайт → Scraper (60 мин) → PostgreSQL/PostGIS
                                      ↓

                                      ↓

## Критические риски

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| ANDE меняет HTML структуру | Средняя | Добавить алерт в scraper-логи при ошибке парсинга |
| ANDE данные в PDF | Высокая | Реализовать PDF-парсинг (Приоритет 2) |
| Злоупотребление кнопкой «Нет света» | Средняя | Уже реализовано: правило 3+ меток в 500м |
| Геокодинг точность ~60% | Высокая | Nominatim бесплатный, достаточно для MVP |
| Admin endpoints небезопасны | Низкая (внутренний инструмент) | Закрыть после MVP через API key |
